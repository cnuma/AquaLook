## 7. Risques et limites

- La connexion prend ~1,5 s de plus (scan) ; le nœud lointain n'apparaît
  pas toujours dans un scan à 150 ms par canal (2 nœuds vus une fois sur 5).
- Le module ne change pas de nœud tant que la connexion tient (point 2,
  non implémenté) : un nœud qui se dégrade sans couper n'est pas quitté.
- Le scan Web `?refresh=1` pendant une connexion en cours n'est pas
  coordonné finement avec le scan de connexion (garde `_scanPending` seule).
- D9 toujours ouverte : la release GitHub ne contient pas de binaire S3.
- Restent valables : §7 du checkpoint `cd09199` (mot de passe de banc
  divulgué, HTTP en clair, secret NVS en clair, outils fuzz sans session).

## 9. Procédure exacte de reprise

```powershell
git fetch origin
git checkout main
git pull --ff-only
git log --oneline -3
git status --short
git -c core.whitespace=cr-at-eol diff --check
python tools/soak/announce_reboot.py
pio run -e ProgrammeArrosage_s3 -t upload --upload-port <PORT_COM>
pio device monitor -p <PORT_COM> -b 115200 --dtr 1 --rts 0
```

Port COM à redemander. Flash de `.141` et dépôt SD autorisés d'office.
Écrire sur le module : `python tools/module_session.py login|state|post …`.
Contrôles sans session : `GET /api/diagnostics` (`build`, `wifi.bssid`),
`/api/logs.txt` (lignes `WiFi: cible`, `WiFi: connecte`). Scan des nœuds
(sous session) : `GET /api/wifi/scan?refresh=1` puis `?all=1`. Reset matériel
à distance : `python ~/.platformio/packages/tool-esptoolpy/esptool.py --chip
esp32s3 --port <PORT_COM> --after hard_reset chip_id` (précédé de
`announce_reboot.py`).

Pièges : `git diff --check` avec `-c core.whitespace=cr-at-eol` ; chaque
connexion refusée compte dans la limite par IP (5 essais) ;
`announce_reboot.py` modifie `tools/soak/ledger.json` ; un heredoc mange les
antislashs (passer par `chr(92)` ou une autre ancre) ; Windows peut verrouiller
`platformio.ini` juste après un build (réessayer la fusion).
