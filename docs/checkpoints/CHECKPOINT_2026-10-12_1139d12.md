### Incident du 12 oct. 2026 (soir) — `.env` du serveur

Le `.env` local (identifiants FTP) a été envoyé par FTP à la racine du site,
remplaçant le `.env` du serveur, puis supprimé : le service n'avait plus de
réglages (`/health` → base injoignable, console 503, `/v1/*` et espace
utilisateur hors service). Le fichier n'a jamais été lisible depuis le Web
(403 par `.htaccess`). Rétabli par le propriétaire en renvoyant le `.env`
serveur (`cloud/php-mutualized/.env`, sa copie de production) ; vérifié :
`/health` ok, console 401, SMTP « défini (chiffré) » (même `SETTINGS_KEY`),
synchro de `Jardin-01` reprise. L'arrosage n'a jamais été touché.
**Règle** : jamais de `.env` par FTP hors réparation ; publier par
`deploy_cloud.py publier` (n'envoie que des fichiers suivis par Git,
n'efface rien) ; `verifier` après tout envoi manuel.

## 9. Procédure exacte de reprise

```powershell
git fetch origin
git checkout main
git pull --ff-only
git log --oneline -4
git status --short
git -c core.whitespace=cr-at-eol diff --check
python tools/deploy_cloud.py verifier
```

`verifier` est en lecture seule (identifiants FTP du `.env` racine) ; il
doit conclure « Serveur ALIGNE ». Publier : `python tools/deploy_cloud.py
publier` (lancé par le propriétaire). Rien à reflasher.

Banc cloud local **isolé** : copier les fichiers suivis de
`cloud/php-mutualized` dans un dossier temporaire, y écrire un `.env` de
banc (`DB_HOST=127.0.0.1`, `DB_PORT=3307`, `DB_NAME=aqualook_banc_d`,
`DB_USER=root`, `DB_PASSWORD=` vide, `ADMIN_TOKEN` aléatoire), puis dans ce
dossier : `php -d extension=sodium -d extension=pdo_mysql -S
127.0.0.1:8011 router.php` (MariaDB portable :
`C:\Users\Emman\mariadb-local\mariadb-12.3.2-winx64`, port 3307).
`/health` doit montrer `"dbPassword":false` (preuve qu'on n'est pas sur
la production). Banc éditeur : `python tools/editeur_banc.py`. Contrôle du
site : `python tools/web_security_probe.py`. Pour un développement
firmware, demander le port COM, puis :

```powershell
python tools/soak/announce_reboot.py
pio run -e ProgrammeArrosage_s3 -t upload --upload-port <PORT_COM>
pio device monitor -p <PORT_COM> -b 115200 --dtr 1 --rts 0
```
