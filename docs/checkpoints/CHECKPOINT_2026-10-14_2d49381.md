## 3. Ce qui a été fait

### 3.1 Chaîne de release (P1.4, D021)

- `.github/workflows/ota-release.yml` : sur étiquette `vX.Y.Z` (= `VERSION`),
  compile **`ProgrammeArrosage_s3` seul** (binaire de production), produit le
  manifeste à cible unique `s3` et `SHA256SUMS.txt`, crée une release
  **brouillon** ; refuse de modifier une release déjà publiée. Plus de carte
  historique ni de pages Web dans la release.
- `tools/generate_ota_manifest.py` : cible `s3`, carte `jc4827w543c_i`,
  environnement `ProgrammeArrosage_s3`.
- `tools/release_firmware.py` (nouveau) : `verifier` (lecture seule),
  `signer` (contrôle 16 points — version, cible, carte, environnement,
  adresse, taille, SHA-256, image ESP32-S3, binaire de production et non de
  banc —, signe, ajoute le `.sig`, publie comme dernière release, relit ce que
  reçoivent les modules en réessayant 2 min à cause du cache GitHub),
  `publier-sans-signature` (essai du refus seulement).
- `tools/version_build.py` + `src/OtaBuildIdentity.h` : cible `s3` et carte
  `jc4827w543c_i` pour les environnements S3 (**P3.1**) ; carte historique
  `unsupported`. Alias `ProgrammeArrosage_legacy` et `_v4` retirés de
  `platformio.ini`.

### 3.2 Signature du manifeste du programme (P1.9 lot 2b)

- `src/MaintenanceBoot.cpp`, `requireManifestSignature()` appelé dans
  `CHECK_VERSION` : télécharge `<manifeste>.sig`, vérifie avec
  `UpdateSignature::verify` sur les octets exacts **avant** l'analyse ; aucun
  repli non signé. Ligne série `[MAJ-SIGNATURE] manifeste programme
  authentifie|refuse` (catalogue `tools/log_messages.tsv`), avec taille, début
  et dernier octet reçus en cas de refus.

### 3.3 Défaut trouvé et corrigé (`3c0ee1e`)

`fetchManifestUrl` ajoutait un octet parasite (131 octets reçus pour un `.sig`
de 130) : invisible pour le JSON (ArduinoJson ignore la fin), fatal à la
signature (`signature-illisible`). Lecture bornée à `Content-Length`, `read()`
en échec ignoré, corps tronqué refusé (`manifest-truncated`). **Un module en
5.17.1 garde ce défaut et refuse toute release signée** (vérifié) : seul
`.141` l'a eu, il est revenu au banc par USB.

## 8. Risques et limites

- Le cache de GitHub sert l'état précédent environ une minute après une
  publication : une vérification lancée trop tôt lit encore `signature-absente`.
- Un module en 5.17.1 ne peut plus suivre l'OTA : flash USB obligatoire.
- `ubuntu-latest` passe à Ubuntu 26 le 19 oct. (P4.9) ; actions GitHub en
  Node 20 dépréciées (avertissement du run) : à surveiller à la prochaine release.
- Textes d'aide `signature-*` pensés pour les pages Web (P3.16).
