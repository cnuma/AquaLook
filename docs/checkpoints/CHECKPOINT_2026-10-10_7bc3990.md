## 5. Invariants préservés

- Aucune route Web locale ne rattache ni ne détache : seul le LCD (derrière le
  PIN) le demande, via `EventBus`. Annuler un code reste libre.
- Le code court n'est jamais journalisé ; le jeton ne circule qu'en HTTPS (sauf
  serveur d'établi privé), n'est stocké côté serveur qu'en empreinte, rendu
  une seule fois.
- Enrôlement et synchronisation ne tournent jamais ensemble (même tas, même
  chien de garde `PHASE_HARD_DEADLINE_MS`).
- Relais : aucun chemin touché ; une synchro forcée attend la fin d'un arrosage.
- Paramètres serveur réglables depuis la console (`ENROLL_*`) ; rien de secret
  dans Git.
- Identité de build vérifiée sur `.141` (build 1328, `hwId`).

## 7. Risques et limites

- **Identifiant technique figé sur l'ancien nom** (coquille relevée par le
  propriétaire) : un module renommé « Jardin-03 » garde l'identifiant
  `Jardin-01`, ce qui paraît incohérent. `module_id` est la clé de
  l'historique, des sauvegardes, des commandes et du jeton (et le module le
  garde en NVS) : il ne se renomme pas. Pistes : afficher l'identifiant
  matériel `aql-…` plutôt que `module_id` dans « Ce module », ou migrer les
  modules historiques vers `module_id = hw_id` (lot dédié, toutes tables). → §8.1.
- « Oublier le compte » sur le LCD sans détachement en ligne bloque tout
  nouveau rattachement (`403 already_enrolled`) tant que le module n'est pas
  détaché depuis l'espace en ligne : voulu (preuve de possession), à expliquer
  dans l'aide.
- Un tiers qui connaît le `hw_id` d'un module jamais rattaché peut bloquer son
  enrôlement (pas le prendre) ; l'administrateur le lève.
- `FORCE_SYNC_MIN_GAP_SEC` (60 s) est une constante firmware, pas un réglage NVS.
- Le numéro de build et le SHA ne distinguent pas un binaire construit avec
  du code non committé (build 1320 affiché trois fois) ; l'empreinte ELF le fait.
- Accusé de commande (`_ackSyncSoon`) : remet `_lastSyncEpochSec` à 0, ce qui
  repasse par « première échéance » et fait attendre un intervalle complet au
  lieu de partir aussitôt (défaut antérieur, non corrigé).
- Restent valables : §7 de `CHECKPOINT_2026-10-09_370a6eb.md` (délivrabilité
  des mails, mot de passe SMTP en clair en base, PIN 4 chiffres, session Web
  locale absente, 10 vs 12 caractères, `target=unsupported`).

## 9. Procédure exacte de reprise

```powershell
git fetch origin
git checkout main
git pull --ff-only
git log --oneline -3
git status --short
git checkout -b <feature/...>
```

Demander le port COM courant, puis, pour un changement firmware :

```powershell
git -c core.whitespace=cr-at-eol diff --check
python tools/soak/announce_reboot.py
pio run -e ProgrammeArrosage_s3 -t upload --upload-port <PORT_COM>
pio device monitor -p <PORT_COM> -b 115200 --dtr 1 --rts 0
```

Flash de `.141` autorisé d'office par le propriétaire (10 oct. 2026) ; dépôt
d'une page `data/` sur la SD de `.141` aussi (`/api/debug/deploy-begin`,
`deploy-file?name=…`, `deploy-commit`, puis comparer le SHA-256 servi).
Publication AlwaysData : par le propriétaire (FTP), jamais par l'agent.

Contrôles rapides : `GET /api/diagnostics` (`build`), `GET /api/logs.txt`
(lignes `[ENROLL]`, `CloudSync: cycle`, `Garde anti-boucle`),
`GET /api/adminStatus` (`cloudSync`), `POST /api/cloudSyncNow`,
`GET https://aqualook.alwaysdata.net/health`.

Banc serveur local : MariaDB portable `C:\Users\Emman\mariadb-local`
(`mariadbd.exe --defaults-file=data/my.ini --port=3307`), base séparée
`aqualook_banc_d` (schémas v1 à v6), `DB_NAME=aqualook_banc_d php -d
extension=openssl -S 127.0.0.1:8002 router.php`. Banc Python du lot D : non
versionné (scratchpad de la session) — à recréer si besoin à partir du §3.

Pièges : `git diff --check` simple signale à tort les CR (utiliser
`-c core.whitespace=cr-at-eol`) ; un heredoc bash transforme `'\0'` en vrai
octet NUL dans un source C++ (passer par l'outil d'édition) ; l'énumération
`DISABLED` entre en conflit avec une macro du cœur Arduino ESP32 ; une route
sous `/api/cloudSync/...` est captée par le gestionnaire JSON de
`/api/cloudSync`.
