## 3. Fonctionnalités validées

Toutes validées par l'utilisateur sur `.141` le 6 octobre 2026 au soir
(« tout semble fonctionner »).

1. **Éditeur graphique des scripts** (`/scripts-schema.html`) — logigramme
   contraint de type Grafcet, plein écran sur PC, consultation seule sur
   téléphone. Palette de blocs à gauche, schéma au centre (molette = défiler,
   Ctrl+molette = zoom), réglages du bloc à droite, texte généré et « essai à
   blanc » en bas. Le schéma **produit le texte du langage existant**, compilé
   par `script-lang.js` : le module ne voit que le bytecode habituel.
   Un script non dessinable (variables, calculs, `reste()`, et/ou mélangés…)
   s'ouvre en lecture seule avec renvoi vers l'éditeur texte.
2. **« Arroser » attend la fin de l'arrosage** par défaut (case décochable) :
   `tantque reste(N) > 0 faire attendre 1 fintantque`. Corrige le défaut
   constaté par l'utilisateur (« Répéter 3 fois » ouvrait la zone 3 fois en
   parallèle).
3. **Bouton × de suppression** directement sur chaque bloc.
4. **« Lancer un script »** (`lancer script N`) : un script en démarre un
   autre, qui tourne en parallèle. Le script appelant continue toujours ;
   un refus (déjà en cours, inactif, plus de place, relancé < 5 s) est
   journalisé. **4 scripts simultanés sur S3** (2 sur CYD), annoncés par
   `/api/scripts` (`simultanes`).
5. **Bloc « En parallèle »** (`parallele … avec … finparallele`) : deux
   branches qui partent ensemble ; la suite attend la fin des deux. Sans
   place libre, la branche 2 s'exécute après la branche 1 (journalisé).
   Pas d'imbrication. L'arrêt sur erreur d'une branche arrête le script.
6. **Interrupteur « Actif »** dans la barre du haut de l'éditeur graphique.
7. **Bouton « Phrases »** : édition de la bibliothèque de notifications
   (ajout, modification, suppression), même signature que `scripts.html`.
8. Accueil : le lien « Scripts » ouvre l'éditeur graphique ; `scripts.html`
   a un bouton « Éditeur graphique » et accepte `?i=<emplacement>`.

## 7. Risques et limites

- **CYD** : l'utilisateur a demandé de ne plus compiler la CYD à chaque fois
  (abandon prévu). Mais la CI `platformio-v4-domain.yml` compile encore
  `ProgrammeArrosage` : une casse éventuelle y apparaîtrait.
- **Scripts en cours non persistants** : un redémarrage arrête les scripts
  et leurs branches (comportement inchangé).
- **Capacité** : un bloc parallèle occupe 2 des 4 places ; au-delà, repli
  séquentiel (journalisé).
- **Taille** : 400 octets de bytecode par script ; « Arroser » avec attente
  coûte ~20 octets de plus. L'éditeur affiche la taille en direct.
- **Garde-fous VM** : 6 h d'exécution par script, 100 000 tours de boucle,
  200 000 instructions — l'attente de fin d'arrosage tient dans ces limites.
- **`git diff --check`** signale des « espaces en fin de ligne » sur
  `src/WebManager.cpp` : faux positif (fichier stocké en CRLF dans le dépôt).
- Le banc d'intégration de la page (faux module + Edge sans fenêtre) a été
  utilisé dans la session mais **n'est pas versionné**.
- `AGENTS.md` reste partiellement périmé sur les profils de build
  (Legacy/V4 → `ProgrammeArrosage_s3`), voir `docs/REPRISE_INGENIEUR.md` §1.

## 10. Procédure exacte de reprise

1. Lire `AGENTS.md`, puis `docs/REPRISE_INGENIEUR.md`, puis ce document.
2. Se placer sur la branche :

```powershell
git fetch origin
git checkout feature/scripts-paralleles
git pull --ff-only
git log --oneline -3
git status --short
```

3. Demander le port COM courant (COM4 sur le poste habituel, à reconfirmer).
4. Validation minimale avant tout changement firmware :

```powershell
git diff --check
pio run -e ProgrammeArrosage_s3
pio run -e ProgrammeArrosage_s3 -t upload --upload-port <PORT_COM>
pio device monitor -p <PORT_COM> -b 115200 --dtr 1 --rts 0
```

5. Banc logique de l'éditeur :

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless --disable-gpu --allow-file-access-from-files --dump-dom "file:///<chemin-du-depot>/tools/script_schema_test.html"
```

6. Dépôt direct de pages sur la SD de `.141` (sans carte retirée) :
   `POST /api/debug/deploy-begin`, puis `POST /api/debug/deploy-file?name=<fichier>`
   (corps binaire) par fichier, puis `POST /api/debug/deploy-commit`.

Rappels propres au banc :

- `.141` est un module de test sur le bureau de l'utilisateur : **flashable à
  tout moment, sans contrainte de vanne**.
- Avant un flash pendant la campagne de soak : `python tools/soak/announce_reboot.py`
  (modifie `tools/soak/ledger.json`, à committer).
- Moniteur série S3 : `--dtr 1` obligatoire.
